# Mosaic — 주제별 다중 보드 설계

## 왜
지금까지는 "바이브코딩 연수 게시판" 하나만 쓸 수 있었다. 패들렛이나 띵커벨 보드처럼 주제마다 보드를
하나씩 만들고, 보드마다 고유 링크를 학생에게 주어 다른 보드와 헷갈리지 않게 쓰고 싶다.
교사와 학생 모두 같은 방식으로 쓴다(자료 올리기, 글 남기기). 보드를 만드는 사람은 관리자 한 명이다.

## 결정된 것 (사용자)
- 앱 이름: **Mosaic**
- 새 보드 만들기는 버튼 하나로 하되 **관리자 비밀번호**를 거친다.
- 보드마다 **고유 링크**를 둔다.
- 기존 연수 게시판의 글과 게시판은 그대로 살려 **그룹형 보드 하나**로 남긴다.
- 보드 유형: 지도형, 격자형, 그룹형, 출석부형, 타일형. 추천 유형으로 **스트림형**을 더했다.
- 홈 화면(확정 목업 v8):
  - 보드를 4:3 카드로 나열하고, 화면 폭을 끝까지 채운다(한 줄 개수는 자동).
  - 연한 파스텔 색에 큰 글씨를 쓴다(카드 제목 21px, 보조 글씨 17px).
  - 카드형·목록형·유형별 보기를 고를 수 있다.
  - 보조 글씨는 "유형 · 글 수 · 만든 날짜" 순서이고, 날짜에는 이름표 없이 날짜만 쓴다.
- 출석부형:
  - 참여자마다 지정 칸을 둔다(띵커벨 출석부형 참고).
  - 인원 수를 입력하면(예: 20) 1번~20번 칸이 만들어진다.
- 그룹형: 그룹별 세로 구분을 두고, 그룹이 5개 이하면 화면 너비를 나눠 채운다(띵커벨 그룹형 참고).

## 구조
- **새 컬렉션 `boards`**: 필드는 title, description, type, roster(출석부형), region(지도형), lockHash, createdAt, updatedAt.
- **기본 보드 `main`**: 문서가 없어도 존재하는 그룹형 보드다.
  - `boardId`가 없는 탭과 칼럼은 모두 main 소속으로 본다. 그래서 기존 데이터를 옮기지 않는다.
  - 제목은 기존처럼 `config/site`에서 가져온다.
- **새 보드의 데이터**:
  - 새 보드에 속한 탭과 칼럼에는 `boardId`가 붙는다.
  - 그룹형이 아닌 보드는 글을 담는 보관용 칼럼(`role: "board"`)을 하나 갖는다. 덕분에 카드, 댓글, 첨부, 잠금, 숨김, 복사·이동 코드를 그대로 쓴다.
  - 유형별로 카드에 붙는 필드: 지도형은 `lat`·`lng`, 출석부형은 `rosterName`.
- **출석부 칸 구분**: 칸은 "N번" 번호로 구분한다. 나중에 "3번"을 "3번 김민지"로 바꿔도 그 칸의 글이 그대로 따라간다.
- **라우팅**: 해시 방식이다. `#/`는 홈, `#/b/{boardId}`는 보드다.
- **화면 파일**:
  - 홈은 `js/home.js`가 그린다.
  - 그룹형이 아닌 보드 화면은 `js/boardViews.js`가 그린다.
  - 그룹형은 기존 `ui.js` 코드를 쓴다.
- **지도**: Leaflet 1.9.4(cdnjs)와 OpenStreetMap 타일을 쓴다. 지도형 보드를 처음 열 때만 불러온다.
- **참여자(비관리자) 화면**:
  - 보드 안에서는 홈으로 가는 로고를 숨겨, 공유받은 보드에만 머물게 한다.
  - 홈 주소로 들어오면 목록은 보인다. 하지만 새 보드 만들기, 설정, 삭제는 관리자 비밀번호가 있어야 한다.
- **화면 문구**: "강사"는 "관리자"로, "수강생·연수생"은 "참여자"로 바꿨다.

## 내가 정한 것 (빌더 판단)
- **헤더 버튼 위치**: 비밀번호 변경과 백업 내보내기 버튼은 홈 헤더에만 둔다. 보드 헤더는 글쓰기, 링크 복사, 보드 설정만 남긴다.
- **보드 잠금**: 보드 단위 비밀번호 잠금을 추가했다. 기본 보드는 기존처럼 탭이나 게시판 단위로 잠근다.
- **홈의 "최근 활동"**: 글을 쓸 때마다 `boards/{id}.updatedAt`을 갱신해서 쓴다. 기본 보드도 이때 `boards/main` 문서가 생긴다.
- **글 수**: 칼럼별 집계 쿼리(getCountFromServer)로 세고, 30초 동안 캐시한다.

## 배포 전 필수
Firestore 규칙에 `boards` 컬렉션 허용을 추가해 게시해야 한다(`firestore.rules`에 반영해 두었다). 게시하기 전에는 기본 보드만 보이고, 관리자에게 안내 문구가 뜬다.

## 검증
실제 DB에 쓰지 않으려고, import map으로 Firebase를 메모리 가짜 DB로 바꿔 끼운 테스트 페이지(`.superpowers/mock/`, git 제외)에서 확인했다.
- 보드 만들기, 삭제, 설정, 잠금
- 유형별 글쓰기: 지도 클릭으로 쓰기, 출석부 칸별 쓰기
- 보드 사이 탭과 칼럼 분리
- 홈 보기 전환과 정렬
- boards 접근이 거부될 때의 안내

실제 DB는 읽기 전용으로만 열었고, 기존 탭 2개, 게시판 5개, 글 17개가 그대로 보이는 것을 확인했다.
